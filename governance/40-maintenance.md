# 40 — 制度維護協議

> 讀者：未來想修改本目錄任何檔案、或修改全域/專案指令檔的模型。
> 原則：制度要能演化，但演化必須留痕、可回滾、不越權。

## 修改前的固定動作（無例外）

1. 備份：`cp` 原檔到 `backups/`，檔名格式 `<來源描述>.<yyyymmdd-HHMMSS>`（例：`claude-global-CLAUDE.md.20260703-233941`）。
2. 改完後在該檔底部的「變更紀錄」加一行（格式見下）。
3. 若改的是規則本體（不只是錯字），在回覆中明確告知使用者改了哪條、為什麼。

## 權限分級

### 可自行修改（改完告知即可）
- 修正錯誤事實：路徑失效、工具名變了、harness 能力備忘過時（如 [10-dispatch.md](10-dispatch.md) 最後一節）。
- 新增教訓：往「教訓記錄」追加條目（格式見下）。
- 補範例：為既有規則加正例/反例，不改規則本身。
- 錯字、格式、失效連結。

### 必須先問使用者（提案→同意→才改）
- 新增、刪除、放寬任何**安全紅線**（[50-safety.md](50-safety.md) 與兩個全域 router 的安全節）。
- 改變優先序（使用者指示 > 專案檔 > 制度檔 > skills）。
- 改變語言偏好、溝通風格等使用者偏好。
- 刪除任何既有規則（就算你認為它過時——說明理由請使用者裁決）。
- 大規模重組檔案結構（合併、拆分、改檔名——會弄斷所有 router 引用）。

## 教訓回寫（每次踩坑後的義務）

**觸發**：使用者糾正了你、驗收 FAIL 暴露了流程洞、或你發現制度規則實際上行不通。

**寫到哪**：
- 通用教訓（跨專案適用）→ 追加到本檔底部「教訓記錄」，若教訓大到該成為規則，走上面的權限分級改對應檔。
- 專案教訓 → 該專案的 auto-memory（Claude Code）或專案 CLAUDE.md/AGENTS.md 的慣例節。**注意：worktree 裡的 session 記憶與主專案不相通，在 worktree 學到的教訓要寫進主專案路徑的檔案，不要只寫 worktree 自己的 memory。**

**格式**（一條三行，強制附「如何套用」，只寫發生了什麼的教訓沒有用）：
```
- [yyyy-mm-dd] 情境：一句話。
  教訓：一句話。
  套用：下次遇到什麼訊號、做什麼動作。
```

## 長度預算（超標就精簡，這是硬上限）

| 檔案 | 上限 | 理由 |
|---|---|---|
| `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md` | 60 行 | 每個 session 都載入，行行都是稅 |
| 專案 CLAUDE.md / AGENTS.md | 120 行 | 每個該專案 session 都載入 |
| 本目錄各制度檔 | 300 行 | 按需載入，但太長會被跳讀 |
| 教訓記錄（本檔底部） | 20 條 | 超過就做「畢業」：反覆出現的教訓升格為對應檔的正式規則，一次性的舊教訓移到 `backups/graduated-lessons.md` 存檔 |

**精簡的優先順序**：先合併重複 → 再把「範例、理由」抽到被引用的檔 → 最後才考慮刪規則（刪規則要問使用者）。

## 兩側同步規則

`~/.claude/CLAUDE.md` 與 `~/.codex/AGENTS.md` 是同一套制度的兩個 router。改了一邊的「安全紅線、優先序、路由清單」就必須同步改另一邊；兩邊允許不同的只有 harness 特有內容（skills 清單、工具名）。發現兩邊漂移：以本目錄的制度檔為準修齊。

**跨機器同步**：本目錄與兩個 router、hooks、自製 skills 的正本都在 git repo `~/Developer/GitHub/ai-global`（本目錄即其 `governance/` 的 symlink）。改完制度檔或全域設定 → `git commit && git push`；在另一台機器開工前 → `git pull` 或跑 `/sync-check`。git 歷史是 `backups/` 之外的第二層回滾機制，備份流程照舊。
