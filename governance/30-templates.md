# 30 — 派工與驗收模板

> 依任務選用並刪除不適用欄位，不要求逐字套用。委派方法見 [10-dispatch.md](10-dispatch.md)，授權與驗收標準見 [20-judgment.md](20-judgment.md)。

## 搜尋／研究

```text
目標與動機：【要回答什麼，支撐哪個決定】
範圍與時效：【檔案／主題範圍，資料時點】
驗收條件：【必須回答的問題、需要排除的可能性】
限制：【唯讀、資料敏感性、工具限制】
回報：先給結論，再附檔案路徑:行號或來源URL，區分事實與推論。
說明覆蓋範圍與未查證事項；找不到可以回報，不補造內容。
```

## 實作／重構

```text
目標與動機：【使用者要求與預期行為】
工作位置：【repo、分支、允許修改的檔案／模組】
相關依據：【必要專案慣例與既有決策】
範圍與限制：【已授權內容、不得觸碰範圍、與其他工作的邊界】
驗收條件：【行為要求、風險等級、必要檢查】
重構若要求行為不變：先記錄相關測試基準；不足時補關鍵行為測試。
回報：改動及理由、檔案位置、實際檢查結果、風險與未解事項。
需擴大範圍、缺必要輸入或授權時，依20的判準回報；不要順手修改無關問題。
```

## 獨立審查

審查者的上下文應隔離實作過程；提供原需求與必要環境即可，不附執行者的自我評價。

```text
角色：獨立審查者。
待驗對象：【產出位置／分支／差異範圍】
原始需求與驗收條件：【逐項列出】
風險與環境：【資料／權限／發布影響，允許的安全驗證方式】
實際讀取產出並核對證據，逐項回報PASS、FAIL或未驗證與理由。
程式行為用相關測試或安全操作驗證；文件核對內容、引用與可用性。
驗收條件之外，與本次產出相關的重大安全或資料缺陷仍判FAIL；
一般範圍外建議另列，不擴大修復範圍。
任一必要條件FAIL或未驗證，整體不得PASS；附最短修復或補驗建議。
不用再委派另一位代理審查你的審查。
```

## 交付原則

回報包含結論、關鍵證據、風險與未解事項即可。長產物是否落檔依任務授權與專案文件規範決定；不要以固定字數犧牲完整性，也不要把整段對話或整份檔案當成摘要。
