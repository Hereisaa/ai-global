# 30 — 派工 Prompt 模板

> 用法：複製對應模板，填掉所有 `【】` 空格後送出。**填不出「驗收條件」就代表你還不清楚自己要什麼——先想清楚再派工。**
> 通用規則（model 選擇、回報合約、驗證）見 [10-dispatch.md](10-dispatch.md)。

## 共通尾巴（每個模板最後都附上）

```
回報合約：
- 只回結論、關鍵證據（檔案路徑:行號）、風險與未解事項（沒有寫「無」）。
- 全文 500 字內；超過 50 行的產物寫入【落檔路徑】，回報只給路徑＋三行摘要。
- 不要貼整個檔案內容，不要流水帳。
```

## 1. 搜尋／探索（model：haiku 或 sonnet；Claude Code 用 Explore 型 agent）

```
你在【repo 路徑】。目標：【要找什麼，例如「所有呼叫 FinMind API 的位置」】。
動機：【為什麼找，例如「準備把 API 層抽象化，需要完整呼叫點清單」】。
範圍：【目錄限定／全 repo】；搜尋廣度：【medium／very thorough】。

驗收條件：
- 每個結果附 檔案路徑:行號 與一句話說明該處在做什麼。
- 明確說明你搜了哪些關鍵字／模式，讓我能判斷有沒有漏。
- 找不到也是合法答案，但要列出已排除的可能位置。
```

## 2. 實作（model：sonnet；跨模組取捨或安全敏感升 opus）

```
你在【repo 路徑】，分支【分支名】。目標：【要實作什麼】。
動機：【使用者原話或需求背景——一到三句】。
既有慣例：先讀【相關檔案或專案 CLAUDE.md 路徑】，新碼要長得像舊碼。
範圍限制：只准動【目錄／檔案清單】；要動範圍外的檔案就停下來回報，不要動手。

驗收條件：
- 【行為條件，例如「/stock 頁的圖表能切換 TWD/USD」】
- 執行【npm run test / tsc --noEmit 等專案指令】全數通過，回報中附輸出關鍵行。
- 不留 debug print、註解掉的舊碼。

回報格式：改了哪些檔（路徑:行號區間）、每檔一句話說明、測試輸出關鍵行。
```

## 3. 重構（model：sonnet；介面設計先由 opus 出方案）

```
你在【repo 路徑】。目標：把【對象】重構為【目標形態】，行為不得改變。
動機:【為什麼重構】。

鐵律：這是行為保持性重構。開始前先跑【測試指令】記錄基準結果；
結束後重跑，結果必須與基準完全一致。若發現既有測試不足以守住行為，
先補測試再重構，並在回報中說明補了什麼。

範圍限制：只准動【清單】。發現「順便也該改」的東西 → 記下來回報，不要動。

驗收條件：
- 測試基準前後一致（附兩次輸出）。
- 【結構性條件，例如「呼叫端不再 import 具體 provider，只 import 介面」】
- git diff --stat 的範圍在限制清單內。
```

## 4. 研究（model：sonnet；結論影響重大決策升 opus）

```
研究問題：【一句話問題】。
動機與決策脈絡：【這份研究要支撐什麼決定】。
時效要求：【例如「以 2026 年現況為準，注意訓練資料可能過時」】。

方法要求：
- 至少【N】個獨立來源；官方文件優先於部落格與論壇。
- 區分「來源明確的事實」與「你的推論」，分開標示。
- 查不到的就寫「未查證」，禁止補完想像。

驗收條件：
- 回答直接回應研究問題（answer-first），再列證據。
- 每個關鍵主張附來源 URL。
- 明列與【我們的假設／現有做法】矛盾的發現（沒有就寫「無」）。

落檔：完整報告寫入【路徑】，回報給路徑＋五行結論。
```

## 5. 審查／驗收（model：sonnet 起跳，仲裁用 opus；必須是 fresh context，不給執行過程）

```
你是驗收者，之前的實作過程你不知道也不需要知道。
待驗對象：【檔案路徑／分支／diff 範圍】。
逐條核對以下驗收條件，每條回報 PASS 或 FAIL 並附證據
（實跑的指令與輸出、或 檔案路徑:行號 的內容）：

1. 【條件一】
2. 【條件二】
3. 【…】

規則：
- 「看起來有做」不是 PASS；每條都要有可複驗的證據。
- 文件類：實際打開檔案核對內容完整、引用路徑逐一確認存在。
- 程式類：實跑【測試／typecheck 指令】，必要時啟動實際操作。
- 發現驗收條件之外的明顯問題 → 列在「額外發現」，不影響 PASS/FAIL 判定。
- 任一條 FAIL 就整體 FAIL，附上最短修復建議。
```

## 反模式（看到自己在寫這些就撕掉重寫）

- 「幫我看一下 X」——沒有驗收條件，agent 會自己發明目標。
- 「盡量完整」「保持高品質」——不可驗證，等於沒寫。改成可勾選的條件。
- 把整段對話歷史貼給 agent——它只需要目標、動機、範圍、驗收；多給的每一段都在稀釋重點。
- 派工後在主對話自己也做一遍——委派就等結果，重複做兩邊都浪費。
