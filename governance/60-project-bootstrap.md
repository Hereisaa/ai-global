# 60 — 專案起手式與文件規範

> 外部參考路徑：本檔的 `../` 連結以 ai-global clone 的 `governance/` 為基準；部署副本請先從 `~/.ai-global/.deploy-state.json` 取得 `source_repo` 再解析。只在任務需要時讀取，不遞迴載入。

> 用於新專案或納入管理的既有專案。單純新增文件只按需讀「文件存放與命名規範」，不觸發起手式或環境盤點。驗證投資依專案壽命與失敗風險決定。
> 授權與驗收依 [20-judgment.md](20-judgment.md)，安全依 [50-safety.md](50-safety.md)。

## 先確認既有環境

補讀尚未載入且適用的專案指令；確認目前分支、未提交變更、runtime（程式執行環境）、套件管理器、lockfile（固定依賴版本的檔案）與可用檢查指令。沿用已運作的配置，不為套模板另建重複制度。

## 依壽命與風險配置

| 專案 | 最小配置 |
|---|---|
| T1 短期實驗 | 簡短專案說明、可重現執行方式、核心路徑驗證；需要環境變數時才建不含秘密的範例 |
| T2 會持續維護 | 加入相關自動檢查與最小 CI；記錄重要設計決策，讓後續工作能接續 |
| T3 長期或有使用者 | 維護 CI、部署與回復程序；按失敗影響增加整合測試、權限控制及審查 |

這是配置起點，不是固定時間門檻。短期實驗若涉及敏感資料、對外操作或不可逆影響，也須採用對應風險控制；純文件或靜態資料專案不必假造 typecheck 或零測試來滿足清單。獨立審查的條件依 20，不要求每次小改都派代理。

## 專案指令的最小內容

- 專案用途與重要結構。
- 已確認可執行的啟動、檢查與測試指令；不適用者省略。
- 不能由程式碼直接推知的慣例、授權邊界與已鎖定決策位置。
- 按需文件路由；避免把所有手冊直接載入每次對話。

共用規則選一份正本；依各工具載入機制建立簡短入口，避免循環引用。Claude Code 可由 CLAUDE.md 以 `@AGENTS.md` 匯入正本；Codex 的檔案探索與上限見 [執行環境參考](../docs/reference/agent-runtime.md)。檔案存在不等於當前工作階段已讀取。

## CI 與 hooks

CI（持續整合）應重現專案實際檢查：使用專案宣告的 runtime、套件管理器與 lockfile 安裝方式，再執行與變更相關的 lint、型別檢查或測試。新增工作流程時核對官方 action 現行版本及相容性，不照抄固定 Node 或 action 版本。

先確認工作流程能觸發、失敗會回報；要阻擋合併還須核對遠端 required checks 等保護設定。CI 檔案存在或本地測試通過，都不能證明遠端保護已生效。

Hooks（在指定事件自動執行的程式）用於及早回饋；設定前查工具現行 schema，並測試允許與拒絕案例。執行後 hook 無法撤銷已做的動作，本地 hook 也不等同遠端合併保護。不要為每次小改啟動不相關的全套測試。

## 決策日誌

需要跨工作階段保留的重要決策可記在 `docs/decisions.md`，例如：

```markdown
- [yyyy-mm-dd] 決策：一句話。
  理由：限制與取捨。
  適用範圍：哪些情境適用，何時應重評。
```

只記錄本次已授權、已確立的專案決策；候選想法保留為提案。

## 文件存放與命名規範

先沿用專案明定的文件慣例；未明定時使用下表。未知分類優先放既有最接近的位置或 `docs/reference/`，不因一般命名選擇反覆詢問使用者。

| 性質 | 位置與檔名 |
|---|---|
| 設計規格 | `docs/specs/yyyy-mm-dd-<topic>-design.md` |
| 執行計畫 | `docs/plans/yyyy-mm-dd-<topic>.md` |
| 長青參考、SOP、手冊 | `docs/reference/<topic>.md` |
| 一次性審查、調查或實測快照 | `docs/reference/yyyy-mm-dd-<topic>.md` |
| 已確立決策 | `docs/decisions.md` |

- 新檔使用小寫 kebab-case；需要日期時用 ISO `yyyy-mm-dd` 前綴。
- `docs/` 根層避免散檔；`docs/decisions.md` 是明確例外，不因此搬移既有決策日誌。
- 檔名應描述主題；既有檔名不溯及改名，避免破壞引用。
- spec／plan 完成後屬歷史參考，不作現行指令。需整理時先保留仍有效的結論，移除流程依 50；不自動清理檔案。

## 工作階段收尾

同步本次變更影響的指令與文件，回報驗證證據及未完成項目。制度或記憶回寫不是固定收尾義務：發現值得長期保留的教訓可提出建議，只有使用者明確要求才寫入，制度修改依 [40-maintenance.md](40-maintenance.md)。
